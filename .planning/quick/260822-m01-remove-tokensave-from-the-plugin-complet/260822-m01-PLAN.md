<objective>
Delete the tokensave MCP integration from agy-delegate at the root, leaving the lean-ctx
half of every shared mechanism byte-for-byte intact in meaning.

Purpose: tokensave granted agy code-graph READ **plus local-project MUTATE** tools
(`readOnlyHint=false`). It was opt-in and is no longer wanted. Removal shrinks the
plugin's attack surface and deletes ~120 lines of atomic-JSON-write machinery whose only
consumer was this feature.

Output: three runtime scripts, the test suite, twelve docs/config files and two dotfiles
with the integration excised; `bash tests/run-tests.sh` green at FAIL=0.

## Locked decisions

- **D-01 — Root-cause deletion, not stubbing.** The registration prompt, `_register_tokensave`,
  `TOKENSAVE_BIN`, the de-registration block, `_MCP_TOKENSAVE`, and both env flags are
  *deleted*. No no-op shims, no `if false`, no deprecation branch.
- **D-02 (overturned) — The FORBIDDEN allowlist catch-all DROPS the name too.** The
  defence-in-depth tradeoff was put to the user explicitly — keep the enumeration in
  `config/policies/{search,shim-default,shim-yolo,shim-sandbox}.md` and the mirroring
  bullet in `config/provider.md`, versus the literal "completely" ask — and the user chose
  full removal ("catch-all mentions gone too"). This is an informed, deliberate override,
  not an oversight. It costs nothing mechanically: the catch-all's own leading clause
  ("Any tool not explicitly PERMITTED above is FORBIDDEN") denies the tool by default with
  no code change, and D-03 strips it from every PERMITTED list, so no policy grants it
  either way. What is lost is one explicitly named vector for an LLM reading the policy —
  legibility, not a boundary (see T-QT01-02). Consequence: the shared catch-all sentence in
  all 4 policy files loses that clause (staying byte-identical, which is what ST1 pins),
  `provider.md`'s catch-all bullet loses it from its slash-list, and ST2 flips from a
  presence assertion to an absence one.
- **D-03 — `PERMITTED` grants DO go.** `config/policies/{code,implement,review-analysis}.md`
  drop `tokensave_context` from their PERMITTED allowlists. Granting a tool the plugin no
  longer registers is dead permission.
- **D-04 — uninstall removes the hint unconditionally.** Post-removal there is nothing
  destructive left to gate: install writes `~/.config/agy-delegate/config.json`, uninstall
  removes it. Keeping a flag named `AGY_UNINSTALL_TOKENSAVE` to gate the deletion of a
  lean-ctx hint would be incoherent. `rm -f` behind an `-f` test keeps I14 idempotency.
- **D-05 — one migration breadcrumb survives, in `.claude/commands/agy-uninstall.md`.**
  Anyone who ran the old opt-in has `tokensave` in their own
  `~/.gemini/antigravity-cli/mcp_config.json`, and after this change no plugin code can
  remove it — a MUTATE-capable grant that would persist silently forever. One sentence
  telling them to delete the key by hand. We do **not** de-register it for them: silently
  rewriting a user's global MCP config without consent is exactly why the old code gated
  that path behind an explicit flag.
- **D-06 — cache format is NOT versioned.** `~/.cache/agy-bridge-mcp` goes from two lines
  to one. A stale two-line cache still reads correctly (`sed -n '1p'` takes lean_ctx;
  line 2 is ignored). Do not invent a cache-invalidation scheme.
