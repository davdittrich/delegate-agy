## Alternatives Considered

The one real mechanism choice in this phase is how a documentation claim gets bound to shipped behaviour so drift fails the suite.

- **Grep-based literal pinning inside the existing bash suite (CHOSEN)**: expected bytes are written verbatim in the test, never extracted from the file under assertion, and counted inside a delimited window. Established in-repo precedent: RB03 at `tests/run-tests.sh:2498-2555`, EC05 at `:2557-2582`, EC06 at `:2584-2685`, all landed under `.planning/phases/03-the-exit-code-contract/03-CONTEXT.md` §D-11 (line 41, 2026). Zero new dependencies; `tests/run-tests.sh` is already the release gate and already runs in milliseconds against `tests/fake-agy.sh`.
- **Golden-file / snapshot diff of the whole Troubleshooting table** (a committed copy plus `diff`, or a snapshot helper on top of `bats-core` — https://bats-core.readthedocs.io/en/stable/, bats-core organization, © 2022, accessed 2026): rejected. A golden file fails on every legitimate wording change, and the fix is always "re-baseline" — a rubber stamp that accepts a drifted claim exactly as readily as a correct one. It also pins nothing to `scripts/`: it compares README to a past README, never to shipped behaviour, which is the entire property S3 needs. Adding `bats-core` would additionally be the first test dependency in a repo whose suite is plain bash.
- **Markdown structural validator over the table** (markdownlint — https://github.com/DavidAnson/markdownlint, micromark/CommonMark-based, accessed 2026): rejected. Its table rules — MD055 table-pipe-style, MD056 table-column-count, MD058 blanks-around-tables, MD060 table-column-style — validate markup shape only. It has no rule that can tie a cell's text to a literal in `scripts/install.sh`, so it cannot detect the drift this phase exists to catch, and it pulls a Node toolchain into a pure-bash project.

**Decided by:** simplicity / lines of code. All three run fast enough to be a non-differentiator at this scale, so performance does not decide; the chosen mechanism adds roughly thirty lines to a file that already implements the same pattern three times, and adds zero dependencies, while both alternatives add a toolchain and still fail to establish the README-to-`scripts/` binding.

**Ceiling of the chosen mechanism, stated rather than hidden:** grep pins literals and row shape. It cannot judge whether a stated reason is true. That judgement is carried by the `<human-check>` blocks in this plan and in 05-02 Task 3, and it is the reason those blocks exist.
