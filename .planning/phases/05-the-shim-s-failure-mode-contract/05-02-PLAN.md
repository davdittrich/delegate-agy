## Alternatives Considered

The mechanism choice — grep-based literal pinning inside the existing bash suite, versus a golden-file/snapshot diff (`bats-core`, https://bats-core.readthedocs.io/en/stable/, bats-core organization © 2022, accessed 2026) or a markdown structural validator (markdownlint, https://github.com/DavidAnson/markdownlint, micromark/CommonMark-based, accessed 2026) — is made once for the whole phase in `05-01-PLAN.md`'s "Alternatives Considered", with the full comparison and rationale. **Decided by:** simplicity / lines of code; both alternatives add a toolchain and neither can bind a README cell to a literal in `scripts/`, which is the property S3 needs. This plan extends the chosen mechanism and makes no new mechanism choice of its own.

One choice IS local to this plan: how the changed-file blast-radius check is scoped.

- **Diff against a phase-start `git status --porcelain` baseline (CHOSEN)**: `git-status` porcelain v1 format, stable by contract — https://git-scm.com/docs/git-status (Git documentation, accessed 2026). Costs one file and one `diff`; attributes exactly the lines this phase added.
- **Assert against the whole worktree** (`git diff --name-only` lists only the expected paths): rejected — https://git-scm.com/docs/git-diff (Git documentation, accessed 2026). The worktree already carries pre-existing modifications to planning and support files this phase did not introduce, so the assertion either fails spuriously or, if loosened to pass, credits Phase 5 with changes it did not make. Codex flagged exactly this.
- **Run the check inside a clean `git worktree add` clone**: rejected — https://git-scm.com/docs/git-worktree (Git documentation, accessed 2026). It gives a true zero baseline, but the phase's own edits live in the dirty tree, so the check would have to be run after committing — which is after the point where the answer is useful — and `git worktree` setup is more machinery than a `diff` against a text file.

**Decided by:** simplicity / lines of code, again: two commands and one temp file, versus a second checkout.
