## Fixed Issues

### WR-01: Three of four probe scratch directories are cleaned up only on the happy path, not on interrupt

**Files modified:** `tests/contract-check.sh`
**Commit:** `7d3fc5f`
**Applied fix:** Added a single, cumulative EXIT trap (`_CC_CLEANUP_DIRS`
array + `_cc_register_cleanup()` + `_cc_cleanup_all()`, installed once near
the top of the script, before the byte-identical `run_bounded` block so
that pinned block stays untouched) and registered every `mktemp -d` call
site with it: `_cc_preflight`'s `_CC_SCRATCH` (replacing its own
now-redundant local trap), `_cc_probe_invalid_model_rejection`'s `scratch`,
`_cc_probe_gemini_md_binds`'s `scratch` and `decoy_dir`, and
`_cc_probe_sigterm_and_model_arg`'s `scratch`. Each probe's existing tail
`rm -rf` is kept as the fast path; the cumulative trap is the last line of
defense on interrupt (Ctrl-C, external kill, an outer CI timeout).
Implemented the loop as a named function (`_cc_cleanup_all`) rather than an
inline `for` loop inside the single-quoted `trap` string — the inline form
triggers a shellcheck SC2154 false positive (`_d is referenced but not
assigned`) that a named function does not. Orchestrator verified: no other
`trap ... EXIT` call site exists in the file (the run_bounded block's
TERM/INT/HUP traps are per-call, saved and restored, unrelated to EXIT), so
this is the sole, authoritative EXIT trap for the script's whole life.
