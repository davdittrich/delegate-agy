# Phase 1.5: Contract check against a real agy - Context

**Gathered:** 2026-08-19
**Status:** Ready for planning

<domain>
## Phase Boundary

One repo-local command, `tests/contract-check.sh`, interrogates the **real** `agy` binary about the assumptions this plugin is built on and emits an assumption ledger: each assumption is *verified*, *contradicted*, or *unverified*, with the evidence it rests on. Its captured output lands in `tests/` fixtures that `tests/fake-agy.sh` reads at runtime, so the suite's fake tracks real output instead of a hypothesis. README and REQUIREMENTS.md then state the verified behavior as fact, carrying the `agy` version and the date it was verified against.

**In scope:** `tests/contract-check.sh` (new); `tests/fixtures/` (new); `tests/fake-agy.sh`'s canned `models` block and any suite case that breaks when the real list replaces it; the `run-tests.sh` cases that pin the isolation invariant, the unverified path, and README-to-fixture provenance; README's model-name statement and the line naming the check; REQUIREMENTS.md's S5 constraint line and traceability row; tickets `delegate-agy-xfa` and `delegate-agy-9qp`.

**Out of scope:** every shipped script — `scripts/agy_bridge.sh`, `scripts/gemini_shim.sh`, `scripts/install.sh`, `scripts/uninstall.sh` are not edited by this phase (the `run_bounded` block is *copied out of* them, not changed in them). Acting on what the check finds: a contradicted row becomes a ticket for the phase that owns the behavior (S1 → Phase 2, R5/R6 → Phase 3, S3 → Phase 5), not a fix here. Phase 6's release gate is deliberately not widened — see D-05.

</domain>

<decisions>
## Implementation Decisions

### Harness — where the check lives and how it stays out of the suite

- **D-01:** The check is `tests/contract-check.sh`, repo-only. It is not shipped, not installed, and gets no launcher. Criterion 3 already puts the fixtures under `tests/`, so capture and consumption share a directory. An operator with a clone runs `bash tests/contract-check.sh`; an operator with only an installation cannot run it, and that is accepted. — **Reversibility:** reversible — promoting it to a shipped script later is additive, but it would grow Phase 4's installer surface and Phase 5's failure-mode table, which is why it is not done now.

- **D-02:** Criterion 1's "never invoked by it" is enforced as **the unit suite never reaches a real `agy` through the check**, not as "the suite never names the file". The literal reading collides head-on with criterion 2, which requires the "could not ask" path to be *tested* — and testing it means driving the command. What criterion 1 protects is that `bash tests/run-tests.sh` never depends on a live, billed, network-bound binary; that property is what gets asserted. A `run-tests.sh` case scans its own source and asserts every `contract-check.sh` invocation runs under a **sanitized PATH** holding `fake-agy.sh` and no real `agy` — the same D-15 pattern Phase 1 used for the coreutils-less branch, and the same static-scan shape as RB01. The check's real-agy probes stay unreachable from the suite. — **Reversibility:** reversible — the invariant is one test case; tightening or loosening it is local. Recorded explicitly because the narrowing is a *reinterpretation of a success criterion*, and a later reader must find the reasoning rather than the conflict.

- **D-03:** The check bounds its own `agy` calls with a **third verbatim copy** of `run_bounded`, carrying the same `# --- BEGIN run_bounded ---` / `# --- END run_bounded ---` markers. Phase 1's D-08 byte-identical test widens from two files to three. This is chosen over extracting the helper to a sourced file — that would cost `gemini_shim.sh` its standalone property, which is the whole reason D-08 chose duplication — and over hard-requiring coreutils, which would make the check unrunnable on exactly the hosts Phase 1 existed to serve, and would leave the bash-watchdog path with no live exercise anywhere. — **Reversibility:** costly — undoing it means either a third, divergent bounding mechanism in a repo whose Phase 1 exists to eliminate exactly that, or the shared-file extraction D-08 declined. Both re-open a settled decision.

- **D-04:** Output is an **assumption ledger, not a PASS/FAIL run**. One line per assumption: name, verdict, and the evidence it rests on. The header carries the `agy` version, the capture date, and how many billed calls the run made. It deliberately does not reuse `run-tests.sh`'s `ok`/`bad` bookkeeping or its `PASS=n FAIL=n` summary, so nobody mistakes a green line for a unit-test pass or wires it into a gate by muscle memory. — **Reversibility:** reversible.

- **D-05:** Phase 6's "both suites pass" gate is **not** widened to include the contract check. Making a release gate depend on a live third-party binary means an agy outage blocks a tag. The check's verdicts inform the release; they do not gate it. State this where the gate is written, so the omission reads as a decision rather than an oversight. — **Reversibility:** reversible.

### Verdict — what the check reports and how "could not ask" is proven

- **D-06:** Every assumption carries one of **three** states: *verified* (asked and agy agrees with what the repo believes), *contradicted* (asked and agy disagrees), *unverified* (could not ask). The run's exit code preserves the distinction: `0` when every assumption is verified, one distinct non-zero code when any assumption is unverified, another when any is contradicted. Collapsing the latter two into a single non-zero loses exactly the distinction criterion 2 was written to preserve — "agy was unreachable" and "agy contradicts the docs" demand different responses. Criterion 2's "never reports pass" therefore holds in `$?`, not only in the ledger text. — **Reversibility:** costly — the codes get documented next to R5's table and an operator may script against them; changing them later is a doc-plus-caller change, though no external consumer exists yet.

- **D-07:** The check's exit codes are **disjoint from R5's** `2` / `3` / `124` / `127` / `137`, so no reader confuses a check verdict with a bridge exit and Phase 3 does not inherit a contract it did not write. A bounded probe that times out internally still sees `124` from `run_bounded`; that becomes an *unverified* row in the ledger, never the check's own exit status. Both the numbers and this mapping are stated in README alongside R5's table. — **Reversibility:** reversible.

- **D-08:** The "could not ask" path is tested from `run-tests.sh`, driving `contract-check.sh` under a sanitized PATH in **two** shapes: (a) `fake-agy.sh` in its SIGTERM-ignoring hang mode, and (b) no `agy` on PATH at all. Each case asserts the distinct unverified exit code, that the ledger **names the assumption** it could not settle, and `_ELAPSED` under the bound — reusing the outer-`timeout` pattern T4/T5/SH11 already established, so a regression to unbounded fails in seconds rather than stalling for the fixture's full sleep. The absent-binary case alone is not sufficient: the hang is the path the `-k` bound exists for, and it is the one criterion 2 names first. — **Reversibility:** reversible.

### Probes — which assumptions get asked, and what each costs

- **D-09:** Seven assumptions. Criterion 1's three — what `agy models` emits; whether `--model` accepts ids, display names, or both; whether a per-run `GEMINI.md` in the working directory actually binds — plus four that earn their place: the **invalid-model rejection** (criterion 3 names its fixture by hand, and it is the evidence that the id-vs-display-name answer is not accidental); the **non-`gemini-` rows** in the live list (`claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium` — the fake emits none, so no test has ever seen a list the anchored `^gemini-[0-9.]+-<class>$` matchers must *exclude*, and Phase 2's S1 work rests on that); **whether agy ignores SIGTERM** (PROJECT.md flags it as explicitly not established, and R11's whole `-k` escalation rests on one untested observation); and the **`agy --version` string shape** (the ledger header and README's dated claim both quote it, so its format is load-bearing for criterion 4).

- **D-10:** The `GEMINI.md`-binding assumption is probed **through the real bridge** with a policy that forbids a tool, asserting the tool is actually refused. Not the bare-CWD probe: that reproduces an observation already recorded on `delegate-agy-xfa` and leaves the ticket's actual question — whether the `--sandbox` and `--add-dir WORK_DIR` the bridge additionally passes constrain discovery — unanswered. This is the phase's one structurally necessary billed delegation. — **Reversibility:** reversible.

- **D-11:** R6's `rc=0`-with-empty-stdout case is probed **deliberately**, by driving agy into the headless permission gate that produced it live on 2026-08-19. If the gate fires, the evidence is captured as a fixture; if agy answers instead, that row reports *unverified*. Opportunistic capture is rejected because the fixture criterion 3 names by hand might then simply never be produced, with nothing reporting its absence. Hand-seeding it from the ticket comment is rejected because it yields a fixture nothing in the repo can regenerate — the exact property criterion 3 asks for. — **Reversibility:** reversible.

- **D-12:** The SIGTERM assumption is probed by issuing a **genuinely slow real delegation with a short bound**, signalling at the bound, and observing whether agy dies on SIGTERM or requires the SIGKILL escalation. Signalling the `models` call instead is cheaper but tests a subcommand that may not share the delegation path's process tree, so a clean death there would not license R11's `-k` on delegations. If agy answers before the bound fires, the row reports *unverified* — a wrong answer here would retroactively justify or condemn a shipped mechanism. — **Reversibility:** reversible.

- **D-13:** A **preflight** runs first: bounded `agy --version` and `agy models`, both cheap and non-generating. If either fails, every delegation-dependent assumption reports *unverified* immediately and **no billed call is made**. If both pass, the full probe set runs and the ledger header states how many billed calls it made. A tiered `--full` flag was rejected: the default run would then be unable to satisfy criteria 1 and 3, making the useful mode the non-default one. A confirmation prompt was rejected as it makes the check non-scriptable without adding a `--yes` surface. — **Reversibility:** reversible.

### Fixtures — how captured output reaches the fake

- **D-14:** Captured output lands in `tests/fixtures/` and **`fake-agy.sh` reads the fixture files at runtime** rather than carrying a canned `printf` block. One source of truth, no codegen step, and no drift test needed — the fake cannot disagree with the fixture because it has no independent copy. Accepted costs: the fake stops being a single self-contained file, and a missing or unreadable fixture becomes a new failure mode the fake must handle explicitly (fail loudly and name the missing file — never silently emit nothing, which is the degraded-list shape S1 exists to catch). — **Reversibility:** costly — reverting to a standalone fake means reinstating the canned block plus the drift test this decision avoids, and every case that reads a fixture would need rewriting.

- **D-15:** The fake's current **8 two-segment gemini ids are replaced wholesale** by the captured 14-line list, non-`gemini-` rows included. Whatever goes red gets fixed. Keeping the old list beside the real one, or adding a per-case override to select the old shape, would leave the suite passing against a list agy stopped emitting — which is the originating 1.6.1 bug's exact shape and the hypothesis this phase exists to kill. Any assertion that breaks was asserting against output the real binary does not produce. — **Reversibility:** costly — the churn lands across the ~89-case suite in one change; splitting it later means re-introducing a second model list.

- **D-16:** Each fixture carries a header recording the **`agy` version and the capture date**. README quotes both verbatim, as fixed literals defined once — the same rule Phase 1's D-10 set for the bound warning and the 124 marker. A `run-tests.sh` case asserts README's version/date strings match the fixture headers, so editing one without the other goes red **with no live agy involved**. The check additionally comparing the live `agy --version` against README was considered and left out of the binding mechanism: it catches real-world drift but detects nothing until someone spends quota, so it cannot be what holds the document to the evidence. — **Reversibility:** reversible.

### Documentation obligations (part of this phase, not a follow-up)

- **D-17:** README states as fact that `--model` accepts **both** ids and display names, carrying the agy version and verification date from D-16's fixture headers. Any wording implying the behavior is assumed or unverified is removed in the same change. README also names `tests/contract-check.sh`, its exit codes (D-07), and that it spends real quota.

- **D-18:** REQUIREMENTS.md carries two stale claims that criterion 4's "No document may claim the assumption is unverified" forbids: S5's constraint line ("cannot be satisfied on the current machine — agy is unresponsive and returns 124") and the traceability row `S5 | Phase 7 | open, externally blocked (agy returns 124 on every call)`. Both are corrected here — the phase is 1.5, not 7, and the premise is disproven. This follows Phase 1's D-17/D-18 precedent: a sentence the change falsifies is fixed in the same change, never filed as a follow-up. `delegate-agy-9qp` closes when these land; `delegate-agy-xfa` resolves with the ledger's verdict on D-10, whichever way it goes.

### Claude's Discretion

- **Exact exit-code numbers** — subject to D-07 (disjoint from R5's five) and D-06 (unverified distinguishable from contradicted). Any consistent choice is fine as long as README states it.
- **Fixture file layout and naming** under `tests/fixtures/`, and the header format that carries version and date — subject to D-16's assertion being writable against it.
- **Ledger line format** — subject to D-04 (name, verdict, evidence; header carries version, date, billed-call count) and D-08 (the unverified row must name the assumption).
- **The forbidden tool and prompt wording** for D-10's policy probe — subject to using the real bridge and a policy shaped like the existing `config/policies/*.md` files, not a bespoke one-off.
- **Whether the seven probes run in a fixed order** and whether a contradicted early row short-circuits later ones. Default to running all seven and reporting all seven; a partial ledger is less useful than a complete one.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`run_bounded` with its BEGIN/END markers** — already duplicated in both shipped scripts and locked by a byte-identical test; D-03 makes the check its third consumer, so the check bounds agy by exactly the mechanism it is auditing.
- **The sanitized-PATH scratch dir** (Phase 1 D-15) — a directory holding only the fake and no `timeout`/`gtimeout`; D-02 and D-08 reuse it to keep the real binary out of the suite.
- **`fake-agy.sh`'s SIGTERM-ignoring hang mode** — built in Phase 1 for the runtime bound proofs; D-08's hang case needs no new fixture mode.
- **The outer-`timeout` case pattern** (T4/T5/SH11, `tests/run-tests.sh:940-948`) — wraps a hang-driving invocation so a regression to unbounded fails in ~30s instead of stalling ~300s, and asserts `_ELAPSED` alongside exit code.
- **`FAKE_AGY_DUMP_ARGV`** — observational argv capture already in the fake; useful for asserting what the bridge actually passed during D-10's policy probe.

### Established Patterns
- **`set -u`, never `set -e`, in test files** — the check is a test-side artifact and inherits this; most probe bodies deliberately invoke something expected to fail.
- **Shared `$HOME` across the whole suite run** — any new case writing `$HOME/.cache/*` must `rm -f` before returning, or every later case sees corrupted state. The model cache at `$HOME/.cache/agy-bridge-models` is the specific hazard for anything touching model resolution.
- **`_run` merges stderr into stdout** — a probe that must prove something reached stderr specifically (the ledger's evidence lines, the unverified marker) captures the streams separately rather than using `_run`.
- **Numbered case prefixes with letter suffixes for variants** — new cases follow the existing convention rather than inventing a prefix; the isolation scan is lint-shaped rather than behavior-shaped and its name should say so.
- **Validate-and-correct, not reject, for optional knobs** — the project's standing rule; the check is a maintainer tool rather than a box-wide shim, so it may be stricter, but its bound knobs should still not silently disable a bound.

### Integration Points
- **`tests/fixtures/` ← `fake-agy.sh`** — the new read path D-14 creates; the missing-fixture failure mode is the seam that must fail loudly rather than emit an empty list.
- **Fixture headers ← README strings** — D-16's assertion is the seam between captured evidence and the document quoting it.
- **The ledger's verdicts → Phases 2, 3, 5** — a contradicted row becomes a ticket for the phase owning that behavior, not a fix here.
- **`run-tests.sh` → `contract-check.sh` under sanitized PATH** — the only permitted invocation shape (D-02), and the thing the isolation scan asserts.

<specifics>
## Specific Ideas

- **The 2026-08-19 probe already predicts four of the seven rows** (recorded verbatim in `delegate-agy-9qp`'s comment): `agy models` returns 14 lines of `id<TAB>display name` in under 30s; live ids are `gemini-3.7/3.6/3.5-flash-{high,medium,low}` and `gemini-3.1-pro-{high,low}` plus `claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`; `--model` accepts both ids and display names; a bogus name gives `rc=1`, "invalid model selection … is not recognized as a known model or custom model in settings", then an `Available models:` list rendered in **display names**. The check must **re-derive** these, not assert them — a probe that hard-codes the expected answer and checks agy agrees is a fixture, not a contract check. The recorded evidence is the reviewer's baseline, not the check's input.

- **Criterion 1 is satisfied more strictly than written, not more loosely.** Its phrase "never invoked by it" is narrowed by D-02 to "the suite never reaches a real agy through it". The suite gains the ability to name the file — and loses, by assertion, any path to the live binary. Record this in the plan so a reviewer reading the criterion literally finds the reasoning instead of a violation.

- **A contradicted row is a success, not a failure of this phase.** The phase delivers a truthful answer; it does not deliver agreement. If the `GEMINI.md` probe shows the bridge's per-type restriction does not bind, that is `delegate-agy-xfa` confirmed and a Phase 5 ticket — the check did its job.

</specifics>

<deferred>
## Deferred Ideas

- **Shipping the check as `scripts/agy-contract-check.sh` with an installed launcher** — considered and declined (D-01). It would let an installed user diagnose their own agy, but grows Phase 4's installer surface and Phase 5's failure-mode table, and it would have to write fixtures into a repo the user may not have. Revisit if a user-reported model-name failure is ever hard to reproduce from a clone.

- **A lint case grepping every tracked doc for "unverified"-shaped claims** — considered under D-18 and declined. It would stop the stale claim from ever reappearing, but its false-positive surface is English prose across README, PROJECT.md, REQUIREMENTS.md and every phase record. Revisit only if the claim actually reappears after this phase.

- **Widening Phase 6's "both suites pass" gate to include the contract check** — explicitly declined (D-05). Recorded here so the omission is findable as a decision.

- **The contract check comparing live `agy --version` against README on every run** — considered as the provenance mechanism and left out of the binding (D-16); a static suite case holds the document to the fixture instead. Worth adding as an extra ledger row later if agy versions start moving faster than the fixtures.

</deferred>
