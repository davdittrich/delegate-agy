## User Constraints (from CONTEXT.md)

### Locked Decisions

**Harness — where the check lives and how it stays out of the suite**

- **D-01:** The check is `tests/contract-check.sh`, repo-only. It is not shipped, not installed, and gets no launcher. Criterion 3 already puts the fixtures under `tests/`, so capture and consumption share a directory. An operator with a clone runs `bash tests/contract-check.sh`; an operator with only an installation cannot run it, and that is accepted. — **Reversibility:** reversible.

- **D-02:** Criterion 1's "never invoked by it" is enforced as **the unit suite never reaches a real `agy` through the check**, not as "the suite never names the file". A `run-tests.sh` case scans its own source and asserts every `contract-check.sh` invocation runs under a **sanitized PATH** holding `fake-agy.sh` and no real `agy` — the same D-15 pattern Phase 1 used, and the same static-scan shape as RB01. The check's real-agy probes stay unreachable from the suite. — **Reversibility:** reversible.

- **D-03:** The check bounds its own `agy` calls with a **third verbatim copy** of `run_bounded`, carrying the same `# --- BEGIN run_bounded ---` / `# --- END run_bounded ---` markers. The block is **~306 lines** (`scripts/agy_bridge.sh:47-352`, `scripts/gemini_shim.sh:64-369`). `_rb_extract` (`tests/run-tests.sh:1208`) already takes a file argument, so widening RB02 (`:1976-1993`) from two extractions to three is mechanical. Chosen over sourcing (costs `gemini_shim.sh` its standalone property) and over hard-requiring coreutils (unrunnable on exactly the hosts Phase 1 exists to serve). — **Reversibility:** costly.

- **D-04:** Output is an **assumption ledger, not a PASS/FAIL run**. One line per assumption: name, verdict, evidence. Header carries `agy` version, capture date, billed-call count. Deliberately does not reuse `run-tests.sh`'s `ok`/`bad`/`PASS=n FAIL=n` bookkeeping. — **Reversibility:** reversible.

- **D-05:** Phase 6's "both suites pass" gate is **not** widened to include the contract check. The check's verdicts inform the release; they do not gate it. — **Reversibility:** reversible.

**Verdict — what the check reports and how "could not ask" is proven**

- **D-06:** Every assumption carries one of **three** states: *verified*, *contradicted*, *unverified*. Exit code preserves the distinction: `0` when every assumption verified, one distinct non-zero code when any is unverified, another when any is contradicted. — **Reversibility:** costly.

- **D-07:** The check's exit codes are **disjoint from R5's** `2`/`3`/`124`/`127`/`137`. A bounded probe that times out internally still sees `124` from `run_bounded`; that becomes an *unverified* row, never the check's own exit status. — **Reversibility:** reversible.

- **D-08:** The "could not ask" path is tested from `run-tests.sh`, driving `contract-check.sh` under a sanitized PATH in **two** shapes: (a) `fake-agy.sh` in SIGTERM-ignoring hang mode, (b) no `agy` on PATH at all. Each case asserts the distinct unverified exit code, that the ledger **names the assumption** it could not settle, and `_ELAPSED` under the bound — "reusing the outer-`timeout` pattern T4/T5/SH11 already established, so a regression to unbounded fails in seconds rather than stalling for the fixture's full sleep." **Research correction:** T4 (`:618-628`) and T5 (`:630-639`) do NOT use an external `timeout` wrapper — see Pitfall 3 below. Only SH11 (`:1060`) wraps with a literal `timeout 30`. — **Reversibility:** reversible.

**Probes — which assumptions get asked, and what each costs**

- **D-09:** Seven assumptions: (1) what `agy models` emits, (2) whether `--model` accepts ids/display-names/both, (3) whether a per-run `GEMINI.md` in the working directory actually binds, (4) invalid-model rejection, (5) non-`gemini-` rows in the live list, (6) whether agy ignores SIGTERM, (7) the `agy --version` string shape.

- **D-10:** The `GEMINI.md`-binding assumption is probed **through the real bridge** with a policy that forbids a tool, asserting the tool is actually refused. Not the bare-CWD probe. This is the phase's one structurally necessary billed delegation. — **Reversibility:** reversible.

- **D-11:** R6's `rc=0`-with-empty-stdout case is probed **deliberately**, by driving agy into the headless permission gate that produced it live on 2026-08-19. If the gate fires, evidence is captured as a fixture; if agy answers instead, that row reports *unverified*. Opportunistic capture and hand-seeding are both rejected. — **Reversibility:** reversible.

- **D-12:** The SIGTERM assumption is probed by issuing a **genuinely slow real delegation with a short bound**, signalling at the bound, and observing whether agy dies on SIGTERM or requires SIGKILL escalation. Signalling `models` instead is rejected (may not share the delegation path's process tree). — **Reversibility:** reversible.

- **D-12a:** D-11 and D-12 both route a non-reproducing probe to *unverified* — honest but not an answer. Both must specify their attempt concretely enough to be repeatable and criticised: D-12 states the payload shape and the exact bound it signals at; D-11 states the tool and the gate it drives at. Where a probe reports *unverified*, the ledger row records **what was attempted**, not only that it failed. A permanently-unverified D-11 is a known gap and must be stated as one.

- **D-13:** A **preflight** runs first: bounded `agy --version` and `agy models`, both cheap and non-generating. If either fails, every delegation-dependent assumption reports *unverified* immediately and **no billed call is made**. If both pass, the full probe set runs and the ledger header states how many billed calls it made. A tiered `--full` flag and a confirmation prompt were both rejected. — **Reversibility:** reversible.

**Fixtures — how captured output reaches the fake**

- **D-14:** Captured output lands in `tests/fixtures/` and **`fake-agy.sh` reads the fixture files at runtime** rather than carrying a canned `printf` block. Accepted costs: the fake stops being self-contained; a missing/unreadable fixture is a new failure mode the fake must handle explicitly (fail loudly, name the missing file — never silently emit nothing). — **Reversibility:** costly.

- **D-14a:** *(Review round, F1.)* `fake-agy.sh` is copied to **six** locations with no `fixtures/` sibling — `tests/run-tests.sh:62`, `:118`, `:2724` (`_fresh_home`), `:2919`, `:3305` — plus two `exec "$HERE/fake-agy.sh"` recorder shims (`:311`, `:532`), and `_install_in` runs under `env -i`, stripping any non-whitelisted variable. Every copy site either copies `fixtures/` beside the binary or exports `AGY_FIXTURES_DIR` — for `_install_in`, that means adding it to the `env -i` whitelist explicitly, "the step that gets forgotten." If no tier resolves, the fake **fails loudly naming the paths it tried**. **Research correction:** an exhaustive re-grep this session found exactly **5** `cp "$HERE/fake-agy.sh" ...` sites, not six — see Pitfall 1 below; the two `exec` sites and the in-place `:1165` call are separate, additional touch points.

## Summary

Phase 1.5 adds one new bash script (`tests/contract-check.sh`) and one new directory (`tests/fixtures/`) to an existing, disciplined ~3486-line hand-rolled test harness (`tests/run-tests.sh`) and two ~700-line production scripts (`scripts/agy_bridge.sh`, `scripts/gemini_shim.sh`). No shipped script changes. The engineering is entirely bash-idiom work: a third verbatim copy of an existing 306-line `run_bounded` watchdog, a fixture-reading rewrite of `tests/fake-agy.sh`'s canned model list, and new suite cases that prove the new script's "could not ask" path without ever touching a real binary. The one genuinely new pattern is the assumption ledger (verified/contradicted/unverified) with its own disjoint exit-code space — everything else is direct reuse of patterns Phase 1 already established and hardened (sanitized-PATH isolation, byte-identical duplication + `_rb_extract`/RB02 comparison, file-capture instead of command-substitution for fd-9-bearing runs, RB03's README-literal-pinning shape).

Three corrections to the phase's own decision record surfaced during this research and must be carried into the plan: (1) D-14a's prose says the fake is copied to "six" locations but enumerates and this session independently re-verified exactly **five** `cp` sites, not six (Pitfall 1); (2) D-08's premise that T4/T5/SH11 share one "outer-timeout pattern" is not accurate — T4/T5 rely on the script's own internal `--timeout N` flag plus a wall-clock assertion, and only SH11 wraps with a literal external `timeout 30` (Pitfall 3); (3) CONTEXT.md's canonical-refs cite `tests/fake-agy.sh:41-51` for the canned model block, but the actual `printf` block is at lines 106-114 (Pitfall 2). None of these change what the phase must build; all three change which lines the planner should point tasks at.

**Primary recommendation:** build `contract-check.sh` as a peer of the two shipped scripts (own `run_bounded` copy, own `TIMEOUT_BIN` probe, own fd-9-style diagnostic channel for ledger evidence lines), drive its "could not ask" tests from `run-tests.sh` the same way SH11 drives the shim's absent-fetch case (external `timeout N` wrapper + sanitized PATH), and fix `fake-agy.sh`'s fixture resolution with the exact three-tier lookup D-14a specifies, threading `AGY_FIXTURES_DIR` through `_install_in`'s `env -i` call explicitly.

### Pattern 1: Third verbatim `run_bounded` copy, extraction-tested (D-03)
**What:** Copy the exact `# --- BEGIN run_bounded ---` … `# --- END run_bounded ---` block (306 lines) into `contract-check.sh` byte-for-byte; widen the existing `_rb_extract`/RB02 comparison from two files to three.
**When to use:** Any new standalone script that must bound an `agy` call the same way the two shipped entry points do.
**Example — the extraction primitive already exists and takes a bare file argument, so no new extraction code is needed:**
```bash
# Source: tests/run-tests.sh:1208-1210 (verbatim, read this session)
_rb_extract() {
    sed -n '/^# --- BEGIN run_bounded ---$/,/^# --- END run_bounded ---$/p' "$1"
}
```
**Example — widening RB02 to a third file is adding one more `_rb_extract` call and one more equality leg, following the exact shape at `tests/run-tests.sh:1986-1997`:**
```bash
# Source: tests/run-tests.sh:1986-1993 (verbatim, read this session — the pattern to extend)
RB02_B="$(_rb_extract "$BRIDGE")"
RB02_S="$(_rb_extract "$SHIM")"
if [[ -n "$RB02_B" && -n "$RB02_S" \
      && "$RB02_B" == *"run_bounded() {"* && "$RB02_S" == *"run_bounded() {"* \
      && "$RB02_B" == "$RB02_S" ]]; then
```

### Pattern 2: File-capture, never command-substitution, for any fd-9-bearing invocation
**What:** When a test drives a script that opens `exec 9>&2` (both shipped scripts do, at `agy_bridge.sh:17` and `gemini_shim.sh:27`), and the invocation spawns `agy` (real or fake) as a descendant, capture stdout/stderr through **files**, never `$(...)` command substitution.
**When to use:** Any new `contract-check.sh` test case in `run-tests.sh` that runs the check against a hanging fake or forks a descendant.
**Why (verbatim comment, read this session):**
```bash
# Source: tests/run-tests.sh:152-168 (paraphrased structure preserved, full comment read this session)
# _run_sanitized captures through a FILE, not command substitution: fd 9
# inheritance under command substitution turned a ~10s red case into a
# ~5min one in a prior incident.
```
**Example — the existing sanitized-invocation helper `contract-check.sh` tests should mirror:**
```bash
# Source: tests/run-tests.sh:169-179 (verbatim, read this session)
_run_sanitized() {
    local __outvar="$1" __rcvar="$2"
    shift 2
    local __dir __rc __f
    __dir="$(_purebin)"
    __f="$SANDBOX/run-sanitized.out"
    PATH="$__dir" "$_TIMEOUT_NET" --foreground -k 5 30 "$@" > "$__f" 2>&1
    __rc=$?
    printf -v "$__outvar" '%s' "$(cat "$__f" 2>/dev/null)"
    printf -v "$__rcvar" '%s' "$__rc"
}
```

### Pattern 3: README-literal-matches-fixture-literal provenance (D-16's model — RB03 precedent)
**What:** Define the expected literal string(s) exactly once in the test file itself (not extracted from source and grepped back into source — that is a tautology), then `grep -qF` both the shipped artifact and README for the same literal.
**When to use:** D-16's assertion that README's stated `agy` version/capture-date match the fixture headers.
**Example (this IS the precedent research question 7 asked for — found and verified this session, full body read):**
```bash
# Source: tests/run-tests.sh:2019-2073 (verbatim structure, read this session)
# RB03: README's troubleshooting table is matched by hand against real output,
# so a paraphrase there is a defect even though nothing crashes. The expected
# bytes are written HERE, not extracted from one file and grepped for in
# another -- extracting from the source and searching the source with it is a
# tautology that passes whatever the strings become.
_RB_WARN_LITERAL='WARNING: timeout/gtimeout not found -- bounding agy with the bash watchdog fallback; install coreutils for process-group kill'
_RB_README="$ROOT/README.md"
grep -qF "$_RB_WARN_LITERAL" "$_RB_README" || { RB03_OK=0; RB03_DETAIL="$RB03_DETAIL readme:warning_missing"; }
```

### Anti-Patterns to Avoid
- **Asserting the contract check's re-derived answer against a hard-coded expected value.** D-09/`<specifics>` is explicit: "a probe that hard-codes the expected answer and checks agy agrees is a fixture, not a contract check." The check must re-derive (e.g. parse `agy models`' own output and check its shape), not assert `"$OUT" == "known-good-string"`.
- **Reusing `_run` (merges stderr into stdout, `tests/run-tests.sh:85-93`) for any case that must prove a ledger evidence line landed on a specific stream.** Follow the SH9 precedent (`:998-1022`, separate-stream capture) instead.
- **Treating "six copy sites" as literal fact when writing D-14a's fix tasks.** See Pitfall 1 — write the task against the verified five `cp` sites plus the two `exec` sites plus the one in-place call, not against an uncorrected count.

### Pitfall 4: `--sandbox` + `--dangerously-skip-permissions` combined may not compose as expected
**What goes wrong:** `agy_bridge.sh`'s real invocation (`:671-689`, verbatim read this session) passes `--sandbox` unconditionally and conditionally adds `--dangerously-skip-permissions` when `AGY_SKIP_PERMISSIONS=1`. Public `agy` documentation search this session surfaced a specific, currently-open upstream report that this exact combination is buggy: `--dangerously-skip-permissions` auto-approves not only regular tool-permission prompts but *also* the prompt asking whether the agent may bypass the sandbox — described as making `--sandbox` "completely ineffective" when combined. If D-10's `GEMINI.md`-binding probe (which asserts a forbidden tool is actually refused) runs with skip-permissions enabled, a bypassed sandbox could make a tool restriction that should hold *appear* to hold for the wrong reason, or fail in a way that looks like a `GEMINI.md`-binding defect but is actually this composition bug.
**Why it happens:** the two flags were designed and documented independently; their interaction is an upstream regression, not a delegate-agy defect.
**How to avoid:** D-10's probe should run WITHOUT `AGY_SKIP_PERMISSIONS=1` (i.e., the default, `--sandbox` alone, no `--dangerously-skip-permissions`) — this is also the realistic path for `--type search`/`review` (no `AGY_SKIP_PERMISSIONS` set per README's type-routing table), so it does not require inventing a new invocation shape. State this explicitly as a probe-design constraint, not an assumption.
**Warning signs:** D-10's probe passing with `AGY_SKIP_PERMISSIONS=1` set should be treated as inconclusive, not as confirmation.
