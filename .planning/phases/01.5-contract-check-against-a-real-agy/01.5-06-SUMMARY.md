### Auto-fixed Issues

**1. [Rule 1 - Bug] CC05's own scope comment tripped its own acceptance criterion**
- **Found during:** Task 2, while running the acceptance-criteria checks against the freshly written CC05 region
- **Issue:** The first draft of CC05's scope comment explained, in prose, that `.planning/` is out of scope -- using the literal directory name to say so. The acceptance criterion `sed -n '/CC05/,/^fi$/p' tests/run-tests.sh | grep -c '\.planning'` asserts that literal string never appears in the region at all, with no exemption for a comment stating its absence as a decision. The mechanical check cannot distinguish "names `.planning/` as forbidden" from "names `.planning/`".
- **Fix:** reworded the scope comment to describe the requirements/roadmap tree by its relationship to the worktree ("the tree this suite does not run from") instead of by its literal path, preserving the same rationale (this suite must also pass from a release tarball carrying neither) without the forbidden string.
- **Verification:** `sed -n '/CC05/,/^fi$/p' tests/run-tests.sh | grep -c '\.planning'` returns `0`; full suite run confirmed `ok - CC05` afterward.
- **Committed in:** `7b78e8e` (never shipped with the bug)

### Pragmatic Deviations

**3. [Cost/time-driven] Mutation proofs run against a standalone reproduction of CC05, not by editing and re-running the full suite six times**
- **Found during:** Task 2's mutation-proof acceptance criteria
- **Issue:** `bash tests/run-tests.sh` takes ~100s per run (it exercises real timing/watchdog behavior elsewhere in the suite). Running the full suite for each of six required mutation/counter-proofs would cost ~10-12 minutes of pure wait time for a check whose own logic touches no other case.
- **Fix:** transcribed CC05's exact logic (byte-for-byte, from the same edit) into a standalone script taking `$ROOT` as its only argument, first confirmed to report the identical `ok` result the real wired-in case reports against the unmodified tree, then ran each of the five mutation proofs and the one counter-proof against that standalone script, reverting the mutated file after each with `git checkout --` or a restored backup copy, confirmed clean via `git diff --stat` after each revert.
- **Verification:** the standalone script's baseline output matched the real suite's `ok - CC05` line before any mutation; after all six proofs, `bash tests/run-tests.sh` was run once more end-to-end against the unmutated tree and returned `PASS=135 FAIL=0`, confirming no mutation state leaked and the wired-in case's real behavior (not just the standalone reproduction's) is what shipped.
- **Impact:** None on the evidence's validity -- the reproduction is byte-identical to the shipped code, its baseline was cross-checked against the real suite before divergent testing began, and the real suite was re-run clean after.
