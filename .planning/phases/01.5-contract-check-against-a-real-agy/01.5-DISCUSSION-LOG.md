## Verdict model & unverified path

### What the exit code means

| Option | Description | Selected |
|--------|-------------|----------|
| Distinct code for any-unverified | Three states: all-verified / any-unverified / any-contradicted. "Could not ask" and "asked and got the wrong answer" demand different responses. | ✓ |
| 0 when all verified, 1 otherwise | Simplest; collapses exactly the distinction criterion 2 preserves. | |
| Always 0; the ledger is the verdict | The check reports, does not gate; a scripted run gets silent green on a run that asked nothing. | |

**User's choice:** Distinct code for any-unverified
**Notes:** → D-06.

### Relationship to R5's exit-code vocabulary

| Option | Description | Selected |
|--------|-------------|----------|
| Disjoint codes, documented alongside R5's | No reader confuses a check verdict with a bridge exit; an internal 124 becomes an unverified row, not the check's exit. | ✓ |
| Reuse R5's vocabulary where it fits | One vocabulary project-wide; conflates "this probe timed out" with the run-level verdict and hands Phase 3 a contract it did not write. | |
| You decide | Claude picks, subject to unverified ≠ contradicted and a README statement. | |

**User's choice:** Disjoint codes
**Notes:** → D-07.

### What drives the mandatory unverified-path test

| Option | Description | Selected |
|--------|-------------|----------|
| Suite case driving the check against the hanging fake + absent binary | Reuses T4/T5/SH11's outer-timeout pattern; asserts distinct code, named assumption, elapsed < bound. | ✓ |
| Self-test mode inside contract-check.sh | Keeps the assertion beside the code; adds a test-only switch D-15 forbade. | |
| Absent-binary case only | Fast and deterministic; skips the hang path the `-k` bound exists for. | |

**User's choice:** Suite case, both shapes
**Notes:** → D-08.

### Conflict: criterion 1 vs criterion 2

The isolation choice put a scan in run-tests.sh asserting it never references contract-check.sh; the unverified-path choice has run-tests.sh invoking it. Surfaced rather than papered over.

| Option | Description | Selected |
|--------|-------------|----------|
| Narrow the prohibition to the real binary | What criterion 1 protects is that the suite never depends on a live agy. The scan asserts the sanitized-PATH shape (D-15 pattern), not the absence of a string. | ✓ |
| Third file: `tests/contract-check-selftest.sh` | Criterion 1 holds word-for-word; costs a third test entry point that can rot unrun. | |
| Split the check: probe core + real-agy driver | Suite tests the verdict logic; the unverified path is then proven for a library, not the command an operator runs. | |

**User's choice:** Narrow the prohibition to the real binary
**Notes:** → D-02, restated. Criterion 1 is satisfied more strictly than written, not more loosely — the suite gains the ability to name the file and loses, by assertion, any path to the live binary.

## Fixtures, regeneration & provenance

### Which direction the fixture data flows

| Option | Description | Selected |
|--------|-------------|----------|
| `fake-agy.sh` reads fixture files at runtime | One source of truth, no codegen, no drift test. Fake stops being self-contained; missing fixture becomes a new failure mode. | ✓ |
| A generator rewrites fake-agy.sh's canned block | Fake stays standalone; costs a codegen step plus a drift test. | |
| Fixtures committed, fake hand-written, drift test only | Cheapest diff; weakest reading of "can be regenerated from". | |

**User's choice:** Fake reads fixtures at runtime
**Notes:** → D-14.

### Replacing the fake's 8-id list with the real 14-line one

| Option | Description | Selected |
|--------|-------------|----------|
| Replace wholesale, fix whatever goes red | A fixture keeping the old ids to avoid churn reinstates the hypothesis this phase exists to kill. | ✓ |
| Add the real fixture alongside; existing tests keep the old list | Zero churn; the suite keeps passing against a list agy stopped emitting — the originating bug's exact shape. | |
| Replace, with a per-test override for the old list | Middle path; the override gets reached for instead of fixing a stale assertion. | |

**User's choice:** Replace wholesale
**Notes:** → D-15.

### What binds README to the evidence

| Option | Description | Selected |
|--------|-------------|----------|
| Fixtures carry provenance; a suite case pins README to it | Version + date in each fixture header; README quotes verbatim; a suite case asserts the match, with no live agy involved. | ✓ |
| README states it; the contract check re-asserts each run | Catches real drift, but detects nothing until someone spends quota. | |
| Both | Two mechanisms, each catching what the other cannot. | |

**User's choice:** Fixtures + suite case
**Notes:** → D-16. Option 2 preserved as a deferred idea.
