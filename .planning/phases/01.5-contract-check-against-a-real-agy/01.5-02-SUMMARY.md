## Decisions Made

- CC02 composes `_purebin()`'s sanitized directory (isolation) with an explicit outer `timeout 30` (SH11's shape) via `env PATH=...`, rather than either (a) reusing `_run_sanitized`'s own `--foreground -k 5 30` net as CC02's bound (rejected in the plan's own Alternatives Considered — would blur the safety-net-vs-mechanism-under-test line), or (b) adding a `timeout` entry to `_purebin()`'s directory the way CC01 added one to its own custom scratch dir (rejected because RB00a already asserts that directory resolves no `timeout`/`gtimeout`, and mutating shared state to fix one case would weaken that assertion for every other caller). `env PATH=...` scopes the replacement to the inner `bash "$CONTRACT_CHECK"` invocation only, leaving the outer `timeout` word resolvable via the harness's own unmodified PATH — a pattern already used once elsewhere in the file (`tests/run-tests.sh:1716`, `_TIMEOUT_NET ... env "PATH=$_RB25_BIN" bash -c ...`), generalized here to the bare-word form.
- CC03's occurrence pattern needed a guard against a false positive from `CONTRACT_CHECK="$HERE/contract-check.sh"` (the harness's own path-building assignment): the literal-path alternative excludes a match immediately preceded by `/`, so a path fragment being *built* is not mistaken for the literal filename used *as a command*.
- D-02's narrowing is restated as a comment directly above CC03 (not only in `01.5-CONTEXT.md`): criterion 1's literal "never invoked by it" collides with criterion 2's requirement that the hang/absent paths be tested, and testing means driving the command.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `_rb_agy_segments`'s noise-stripping erased the exact PATH= signal CC03's clearing rule needs**
- **Found during:** Task 2, first isolated run of `_cc_check_scan` against the real file
- **Issue:** `_rb_agy_segments` (reused per the plan's own instruction) strips a leading `IDENT=` token as noise before returning a segment — correct for RB01's "does this segment start with `run_bounded`" check, but CC01 and CC02's own real invocations both open with a bare `PATH=... cmd` prefix, which is syntactically identical to a plain assignment and so was stripped before CC03 ever saw it. First run reported `violations=3` against the real, correct file — CC01, CC02, and `RB02_C`'s legitimate `_rb_extract` read were all misreported.
- **Fix:** added `_cc_raw_segments`, a sibling to `_rb_agy_segments` sharing the same `_rb_logical_lines`-then-`tr ';|&'` pipeline but WITHOUT the stripping step, used for clearing-detection specifically. Occurrence counting (which doesn't care about leading noise, being a `contains` check) still goes through `_rb_agy_segments` unchanged, so the plan's "reuse the existing splitters" instruction is honored for that half.
- **Files modified:** `tests/run-tests.sh`
- **Verification:** isolated scan re-run against the real file: `violations=0 occurrences=3`. Full suite green.
- **Committed in:** `d5c773a` (Task 2 commit)

**2. [Rule 1 - Bug] `RB02_C`'s legitimate static file read was flagged as a violation**
- **Found during:** Task 2, same debugging pass as above
- **Issue:** `RB02_C="$(_rb_extract "$CONTRACT_CHECK")"` (existing code from plan 01.5-01, line ~1998) is a static `sed` read of `contract-check.sh`'s own source text for RB02's byte-identity check — never an invocation, and structurally cannot reach a real `agy`. Applying RB01's own "any mention is a violation" ceiling literally would have flagged this correct, pre-existing line and made CC03 permanently red against working code.
- **Fix:** added a third clearing form to the production region: a segment mentioning `_rb_extract` anywhere is cleared, since that helper is a well-defined static text-read, already vetted by RB02's own byte-identity test.
- **Files modified:** `tests/run-tests.sh`
- **Verification:** confirmed via the isolated scan and the full suite run.
- **Committed in:** `d5c773a` (Task 2 commit)

**3. [Rule 1 - Bug] the "twoonone" mutation payload's own embedded `;` mis-split its own call site**
- **Found during:** Task 2, after fixing deviations 1 and 2, `violations=1` persisted
- **Issue:** the "twoonone" probe's payload argument literally contained a `;` (`'PATH="$(_purebin)" bash "$CONTRACT_CHECK"; bash "$CONTRACT_CHECK"'`), and since this string is itself part of the file CC03 scans, `tr ';|&'` split the CALL SITE's own text — not just the mutation copy's — into two segments, and the second half (no `_cc03m_probe` prefix, since the split landed mid-string) was reported as a real violation against the correct, unmutated source.
- **Fix:** `_cc03m_probe` now accepts an optional 5th `EXTRA` argument and joins `LINE` and `EXTRA` with a literal `;` inside its own function body (which contains no `CONTRACT_CHECK` text at all, so is immune to the same problem) rather than in any probe's own payload string. The call site became two separator-free string arguments.
- **Files modified:** `tests/run-tests.sh`
- **Verification:** isolated scan: `violations=0 occurrences=3`. CC03m's five probes all pass in isolation. Full suite green.
- **Committed in:** `d5c773a` (Task 2 commit)
