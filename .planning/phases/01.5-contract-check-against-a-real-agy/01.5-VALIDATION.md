## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | None — hand-rolled bash. `tests/run-tests.sh` carries its own `ok()`/`bad()`/`PASS`/`FAIL` bookkeeping (`:71-82`) |
| **Config file** | none — the harness is a single executable file |
| **Quick run command** | `bash tests/run-tests.sh` — no case-filtering flag exists in this harness, so quick and full are the same command |
| **Full suite command** | `bash tests/run-tests.sh` |
| **Estimated runtime** | Minutes, by design. Several cases drive `fake-agy.sh` into a 300s SIGTERM-ignoring hang behind a 30s outer bound (SH11 shape) — that latency is load-bearing and must not be "optimised" away |
| **Baseline** | `PASS=123 FAIL=0` at Phase 1 close (STATE.md). Any new red is this phase's |

**Second entry point, deliberately not part of the above:** `bash tests/contract-check.sh` exercises the **real** `agy`, spends quota, and is never invoked by the unit suite (D-01/D-02). Per D-05 it is **not** a gate — its verdicts inform, they do not block.

---

## Sampling Rate

- **After every task commit:** `bash tests/run-tests.sh` (only granularity available)
- **After every plan wave:** `bash tests/run-tests.sh`, full run
- **Before `/gsd-verify-work`:** full suite green
- **Max feedback latency:** one full-suite run — there is no shorter signal in this harness
- **At least once before the phase is called done:** one manual `bash tests/contract-check.sh` against the real binary. The unit suite can only prove the check's *shape*; criteria 1, 3 and 4 are claims about `agy`, and a phase that never ran the check against `agy` has verified its proxy rather than its deliverable
