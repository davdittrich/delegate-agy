## Alternatives Considered

**Outer-bound shape for the "could not ask" hang case.**

- **SH11's external `timeout N` wrapper (chosen)**: `_run OUT RC timeout 30 bash "$CONTRACT_CHECK" …`, exactly the shape at `tests/run-tests.sh:1060`. Citation: `01.5-RESEARCH.md` §"Pitfall 3: T4/T5/SH11 are not one uniform outer-timeout pattern" (2026), which corrects D-08's own premise after re-reading all three cases.
  Decided by: performance — a regression to an unbounded probe inside `contract-check.sh` fails this case in ~30s instead of stalling the suite for the fixture's full 300s sleep, a 10× feedback-latency difference on the exact failure this case exists to catch.
- **T4/T5's internal `--timeout N` plus a wall-clock assertion**: no external wrapper; the case leans on the bounded script's own bound (`tests/run-tests.sh:618-639`). Rejected on a correctness argument, not a preference: a check whose own bound has regressed cannot be the thing that bounds the test of its own bound, so this shape is structurally unable to fail on the regression it is supposed to catch. Citation: `01.5-RESEARCH.md` §Pitfall 3, `[VERIFIED: tests/run-tests.sh:618-628,630-639,1046-1069,169-179]` (2026); GNU Coreutils Manual §`timeout` invocation, coreutils 9.7 (2025) — <https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html>.
  Decided by: performance — this shape's worst case is an unbounded stall of the whole suite, where the chosen shape's worst case is a 30s failure.
- **`_run_sanitized`'s `"$_TIMEOUT_NET" --foreground -k 5 30` net**: already exists, already whitelist-enforced (`tests/run-tests.sh:169-179`). Not rejected so much as *composed*: CC02 uses the sanitized PATH machinery for isolation and adds SH11's explicit `timeout 30` on top, because the suite-level net is documented at `:131-145` as "a suite-level safety net, never the mechanism under test" and reusing it as the assertion's bound would blur exactly that line. Citation: GNU Coreutils Manual §`timeout` invocation, coreutils 9.7 (2025) — <https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html>, for `--foreground` and `-k` semantics.
  Decided by: simplicity — one explicit wrapper the case owns, rather than overloading a shared net with a second contract.

**Enforcement shape for the isolation invariant.**

- **Static source scan of the harness against itself, RB01's shape (chosen)**: `tests/run-tests.sh:1899-1975` already does exactly this for R11's bounding invariant, complete with an occurrence floor (`RB01_TOTAL -lt 1` ⇒ fail) and RB01m's four mutation probes including the two shapes that walked past an earlier per-line version. Citation: `01-CONTEXT.md` §D-12 "static scan plus runtime proof" (2026); `01.5-CONTEXT.md` §D-02 (2026).
  Decided by: maintenance — the invariant survives every future case anyone adds, without that author needing to know the rule exists.
- **A runtime guard inside `contract-check.sh` that refuses to run when a marker env var is set by the harness**: a test-only override living in the artifact under test. Rejected outright: Phase 1's D-15 set the standing rule that no test-only override may exist in code that ships or is audited, and this would put the suite's convenience inside the deliverable. Citation: `01-CONTEXT.md` §D-15 (2026).
  Decided by: simplicity — zero new surface in the deliverable versus one branch plus a documented knob.
- **Convention plus code review**: no mechanism, a note in the harness header. Rejected because the failure mode is silent and delayed: a future case that reaches a real binary spends quota and passes green. Citation: `01.5-CONTEXT.md` §Specific Ideas, "criterion 1 is satisfied more strictly than written, not more loosely" (2026).
  Decided by: maintenance — an unenforced convention decays at the first contributor who has not read it.

**How CC03 avoids flagging its own mutation fixtures** *(added by the review round — finding F4)*. RB01 does not face this problem: it scans `$BRIDGE` and `$SHIM`, two files *different* from `tests/run-tests.sh`, which is where RB01m's payload strings live (`:1946-1975`). CC03 has no such luxury — D-02's narrowing requires it to scan the harness itself, so CC03m's `_cc03m_probe … 'bash "$CONTRACT_CHECK" …'` payload strings sit inside the scanned file. RB01's stated ceiling is explicit that a mere *mention* counts as a violation (`:1834-1840`), so this is not a bug in the scan to be smartened away; it is a scope question.

- **A marker-bracketed exempt region with its own, narrower clearing rule (chosen)**: `# --- BEGIN cc03-self-exempt ---` / `# --- END cc03-self-exempt ---` around the CC03/CC03m block; inside the bracket an occurrence is cleared only when its segment's first word is `_cc03m_probe`, so a real invocation smuggled in there is still a violation.   Decided by: simplicity — one `sed` range split plus one extra clearing rule, reusing a marker idiom the repo already ships and a segment splitter (`_rb_agy_segments`) that already exists; and the exemption is visible in the source rather than encoded in string trickery.

Rejected on the precedent's own evidence: laundering an expansion so a scanner cannot see it is precisely the shape RB01m's `decoy` probe (`:1974`) exists to catch, and writing that shape deliberately into the checked-in harness would model the evasion the scan must detect. Citation: `tests/run-tests.sh:1963-1975`, RB01m's `decoy` probe and its comment on the two shapes that walked past the per-line scan, read on this tree (2026).

Rejected for the reason already recorded above under §"Enforcement shape": Phase 1's D-15 forbids a test-only override living in audited code, and a runtime tripwire cannot see a call site no test drives — which is the entire class of failure D-02 exists to prevent. Citation: `01-CONTEXT.md` §D-15 (2026).
  Decided by: maintenance — a runtime guard covers only the paths someone remembered to run.
