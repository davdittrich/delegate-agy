## Alternatives Considered

**How the captured model list reaches the fake.**

- **Runtime fixture read (chosen)**: the fake reads `tests/fixtures/agy-models.tsv` when asked for `models`. LOCKED by D-14. One source of truth, no codegen step, and no drift test needed, because the fake has no independent copy to drift from. Citation: `01.5-CONTEXT.md` §D-14 (2026); GNU Bash Reference Manual §3.5.3 and the `read` builtin, bash 5.3 (2025) — <https://www.gnu.org/software/bash/manual/bash.html>. **Decided by: simplicity** — the accepted costs (the fake stops being self-contained; a missing fixture becomes a new failure mode) are both smaller than maintaining two copies plus the test that compares them.
- **Codegen: a build step that regenerates the fake's `printf` block from the fixture**: keeps the fake self-contained and single-file. Rejected because it reintroduces exactly the thing D-14 removes: two copies of the list, and a drift test to prove they agree, plus a generator nobody runs. Citation: `01.5-CONTEXT.md` §D-14's accepted-costs paragraph (2026). **Decided by: LOC** — the generator plus the drift case is strictly more code than the reader.
- **Embed the captured list as a heredoc in the fake**: zero new files, zero resolution logic, no `AGY_FIXTURES_DIR`, no copy-site plumbing. Rejected because it is the current design with fresher data: the next `agy models` change leaves it stale in exactly the way the 1.6.1 incident did, and criterion 3 explicitly asks for fixtures "in a form the fake agy can be regenerated from". Citation: `.planning/ROADMAP.md` §Phase 1.5 criterion 3 (2026). **Decided by: maintenance** — the heredoc is cheaper today and carries the same decay this phase exists to stop.

**How R2 and R4 get their expected model id after the swap.**

- **Re-derive from the fixture with the shipped rule (chosen)**: `_cc_expect_model` runs `grep -E '^gemini-[0-9.]+-<class>$' | sort -V | tail -1` over the fixture's id column, the byte-identical rule from `scripts/agy_bridge.sh:463-532`. Citation: `01.5-CONTEXT.md` §D-15a (2026); GNU Coreutils Manual §`sort` `-V` version sort, coreutils 9.7 (2025) — <https://www.gnu.org/software/coreutils/manual/html_node/sort-invocation.html>. **Decided by: maintenance** — the assertion tracks the fixture forever, and a future recapture cannot leave a stale pin passing silently.
- **Re-pin the assertion to whatever id the current capture selects**: a one-character edit per case. Rejected in D-15a in one sentence: a hard-coded newer id is the same defect one release later. Citation: `01.5-CONTEXT.md` §D-15a (2026). **Decided by: maintenance**.
- **Parse the fixture with `python3 -c` and compute the max version numerically**: more precise than `sort -V` in the abstract. Rejected because it would be a *second* definition of "newest matching id", able to disagree with the shipped one; the point of the assertion is to mirror production exactly, including any quirk. Citation: `01.5-RESEARCH.md` §"Don't Hand-Roll", recording the repo's deliberate `jq`-to-`python3` narrowing at commit `b4b7503` (2026). **Decided by: maintenance**.
