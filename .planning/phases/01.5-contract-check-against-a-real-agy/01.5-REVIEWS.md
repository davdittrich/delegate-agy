# Cross-AI Review — Phase 1.5 (decision record, pre-planning)

## Antigravity Review

### Summary

Phase 1.5's decision record (`01.5-CONTEXT.md`) establishes a well-scoped contract check (`tests/contract-check.sh`) and fixture pipeline (`tests/fixtures/`) to replace speculative assumptions about Google's `agy` CLI with verified, evidence-backed fixtures. Moving this requirement from Phase 7 to 1.5 directly addresses the root cause of the 1.6.x bug cluster (silent drift in `agy models` output and `--model` argument handling). However, the record contains critical operational blind spots: runtime fixture discovery in `fake-agy.sh` breaks under existing isolated test environments (`_fresh_home`/`_install_in` and sandbox copies), D-15's model list update will immediately break existing suite assertions (specifically `R2`), and probes D-11 (headless permission gate) and D-12 (SIGTERM detection via live delegation) risk non-deterministic or permanent *unverified* states due to dependence on external timing and interactive prompts.

### Strengths

- **Direct root-cause remedy with clear phase decoupling** — grounding Phase 2's model-list handling and Phase 5's failure modes in real captured output rather than synthetic hypotheses eliminates the divergence that left `delegate-agy-62x` unverified (`.planning/ROADMAP.md` §Phase 1.5).
- **Rigorous assumption-ledger contract (D-04, D-06, D-07)** — disjoint exit codes separating *verified*, *unverified* and *contradicted* let automation and operators tell external unreachability from a contract violation without colliding with R5's published codes (`README.md:221-240`).
- **Safety preflight and bounded spend (D-13)** — cheap non-generating probes before any billed delegation guarantee an unreachable or unauthenticated `agy` incurs zero API spend.
- **Strict document-provenance assertions (D-16, D-17, D-18)** — requiring exact version and date literals to match between fixture headers and documentation, enforced statically in `run-tests.sh`, keeps docs from drifting off the evidence.

### Concerns

- **HIGH — D-14 runtime fixture discovery breaks in isolated test environments (threatens criterion 3).** `fake-agy.sh` is copied into isolated directories with no `fixtures/` sibling: `tests/run-tests.sh:42`, `:715`, `:910` (master). `_install_in()` runs under `env -i`, stripping non-whitelisted variables. If the fake resolves fixtures relative to `$(dirname "$0")` or an unexported variable, `agy models` fails across all installer tests and sandbox subshells.
- **HIGH — D-15 causes unhandled suite regressions in model sorting.** The live list contains `gemini-3.7-flash-high`; `agy_bridge.sh:153`'s `grep -E '^gemini-[0-9.]+-flash-high$' | sort -V | tail -1` therefore auto-selects 3.7. `R2` (`tests/run-tests.sh:227-233`) explicitly asserts 3.6. The plan must name `R2` and the alias tests, and state whether `config/model-map.json` gains 3.7 entries in this phase or stays pinned.
- **MEDIUM — D-11 / D-12 probe flakiness and non-determinism.** Triggering a headless permission gate deterministically across auth tokens and terminal configurations cannot be guaranteed; if `agy` emits a JSON error or exits non-zero, D-11 reports *unverified* permanently and the R6 fixture is never regenerable. D-12's SIGTERM-at-the-bound is a timing race: a fast answer, an early error, or a failure to spawn children all yield *unverified* rather than a conclusive verdict.
- **LOW — D-03 / D-08 duplication and maintenance burden in test tooling.** Duplicating the `run_bounded` block into `tests/contract-check.sh` widens RB02's byte-identical check to three files, coupling an operator-facing tool to the internal watchdog implementation of two standalone production scripts.

### Suggestions

1. **Robust fixture resolution in `fake-agy.sh`** — a deterministic tiered lookup: `AGY_FIXTURES_DIR` override → `$(dirname "$0")/fixtures` → `$AGY_PLUGIN_DIR/tests/fixtures`. Update `_fresh_home()` and `_install_in()` to either export `AGY_FIXTURES_DIR` into the `env -i` invocation or copy `fixtures/` alongside `$h/bin/agy`.
2. **Reconcile criterion 1 and D-02 in ROADMAP.md** — criterion 1 reads "separate from the unit suite and never invoked by it", which D-02 deliberately narrows. Amend the roadmap text (e.g. "…never exercising a live binary during automated testing") so roadmap and decisions do not contradict.
3. **State `config/model-map.json`'s disposition explicitly** in the phase boundary — updated with `gemini-3.7-*` here, or deferred to Phase 2.
4. **Deterministic fallbacks for D-11 and D-12** — for D-11, if the live gate does not yield rc=0/empty, capture the raw output and annotate the ledger; for D-12, document exact payload and bound values (large synthetic output, strict short timeout) to maximise the chance of intercepting agy in flight.

### Risk Assessment: MEDIUM

The architecture is sound and low-risk to shipped artifacts — no runtime script is modified. Risk is elevated by test-harness fragility: runtime fixture loading breaks sandboxed and installer suites unless path resolution and `env -i` sanitisation are addressed at planning time.
