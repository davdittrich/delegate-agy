<objective>
Mirror the bridge's fix into the shim, and close S4.

`delegate-agy-8ph` forbids a one-sided fix in terms: both writers change together or neither does. Plan 02-01 proved the shape end to end on `scripts/agy_bridge.sh`; this plan applies the identical shape to `scripts/gemini_shim.sh`'s `load_models()`, which writes the same cache file, on the same 60-minute window, with the same atomic write. The two files are line-for-line mirrors of each other in this region by design, and `scripts/gemini_shim.sh:378-386` states why they are not factored into a shared library — so the fix is duplicated deliberately, not abstracted.

One thing does not mirror: the message. The bridge warns; the shim stays silent. That asymmetry is deliberate and already documented at `scripts/gemini_shim.sh:424-426` — this file shadows `gemini` for every PATH caller, so a warning on a normal degraded path would land in every Octopus and Metaswarm log line. D-05 locks it, and a shim warning is a Deferred Idea belonging to Phase 5.

Purpose: make the second writer as safe as the first, so one bad `agy models` reply cannot degrade the other tool for an hour.
Output: the gate and the fallback in `load_models()`, plus SH15, SH15b and SH15c in `tests/run-tests.sh`.
</objective>

## Alternatives Considered

**A. Whether the shim's fix is the bridge's fix duplicated, or the two are factored into one shared implementation.**

- **Duplicate the shape into `load_models()`, independently (chosen)**: LOCKED by D-03's framing and by the file's own recorded rationale. `scripts/gemini_shim.sh:378-386` states the model-resolution block is deliberately not factored into a sourced library because this script installs as `~/.local/bin/gemini` and shadows the real `gemini` for every caller on PATH — a missing helper would break `gemini` box-wide, and roughly twenty duplicated lines is the cheaper failure mode. Citation: `scripts/gemini_shim.sh:378-386`, read on `fix/agy-bridge-resilience` (2026); `02-PATTERNS.md` §"`scripts/gemini_shim.sh`'s `load_models()`" (2026).
  Decided by: maintenance — a shared file introduces a new runtime failure mode on the one script in this repo whose failures reach processes that never heard of this project.
- **Extract the fetch/gate/cache block into a sourced `lib/models.sh`**: the textbook answer to two near-identical blocks, and the only option that makes drift structurally impossible. Rejected for the reason above, and because the divergence this phase itself introduces — the bridge warns, the shim is silent — means the shared function would immediately need a caller-supplied message hook, which is a parameterized abstraction over two call sites. Citation: `02-CONTEXT.md` §D-05, the shim-stays-silent decision (2026); `scripts/gemini_shim.sh:424-426` (2026).
  Decided by: simplicity — one branch and one parameter's worth of abstraction for two call sites is not a saving.
- **A test that pins the two blocks byte-identical, `RB02`'s treatment of `run_bounded`**: keeps the duplication honest without a shared file. Rejected because the two blocks are *not* byte-identical and cannot be — different variable names (`_agy_models` against `raw`), different scope (top-level against function-local), and one carries a warning the other must not. RB02 works precisely because `run_bounded` is genuinely identical text. Citation: `tests/run-tests.sh:2032-2086` (RB02 and RB02m) (2026).
  Decided by: maintenance — a byte-comparison over text that legitimately differs is a test that must be weakened on its first true positive.

**B. What the shim does with a degraded reply when no cache exists.**

- **Leave `raw` holding the degraded reply and let `map_model` handle it, exactly as today (chosen)**: `map_model`'s warning gate at `:459` already tests `LIVE_MODELS` for a `^gemini-` line before warning, so a gemini-less list and an empty one are treated identically — the name passes through unchanged and quietly either way. Leaving `raw` alone therefore changes nothing observable while keeping the shim's branch shape a mirror of the bridge's, where the same choice is load-bearing because it preserves R8's message. Citation: `scripts/gemini_shim.sh:452-461` and `tests/run-tests.sh:1168-1187` (SH14), read on the worktree (2026); `02-01-PLAN.md` §"Alternatives Considered" B (2026).
  Decided by: LOC — zero extra branches, and the two files keep one shape between them.
- **Clear `raw` unconditionally on a degraded reply**: one condition shorter, and observably identical on this side — `load_models()` would emit nothing, `LIVE_MODELS` would be empty, and `map_model` would still pass the name through without warning. Rejected only because it breaks the mirror: the bridge cannot do this without turning R8 red, so adopting it here would leave the two blocks structurally different for no gain, and the next person to compare them would have to rediscover why. Citation: `scripts/agy_bridge.sh:502-517` (2026); `scripts/gemini_shim.sh:378-386` on the mirror being the maintenance contract (2026).
  Decided by: maintenance — the duplication only stays cheap while the two copies stay comparable.

**C. How SH15b proves the cache was preferred over the degraded reply.**

- **`FAKE_AGY_DUMP_ARGV` plus a cache-only model id, SH10's shape (chosen)**: seed the cache with `gemini-7.7-flash-high`, a version that exists in no fixture and no other case, then read the `--model` value agy actually received out of the argv dump.   Decided by: ecosystem — the harness already does this four times; a fifth costs nothing.
- **Asserting on the shim's own stdout**: simpler, no dump file. Rejected because the shim passes the resolved model to agy rather than printing it — stdout carries agy's reply, not the resolution — so this cannot observe the property at all. Citation: `scripts/gemini_shim.sh:548` (`LIVE_MODELS=$(load_models)`) and the delegation call site (2026).
  Decided by: simplicity — among options that can observe the resolution, this is not one.
