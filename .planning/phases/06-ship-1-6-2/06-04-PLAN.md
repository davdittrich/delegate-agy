<objective>
Two standing structural guards, both on the test side, neither changing a byte of shipped script:

- **D-05 / `delegate-agy-u1z`** — add `IN02`, an `IN01`-shaped cross-file **joint presence-and-form guard** over the twin `grep -qxF` model-validation sites in the bridge and the shim, so a one-sided edit to the pair fails with a message naming both counts. Name it that way and not "structural-equality": IN02 asserts that each file contains its own expected expression exactly once, which catches deletion and edits to the guarded form, and does not and cannot detect semantic divergence between two expressions that both still match. The two sites necessarily reference different variables, so literal equality was never available; the invariant IN02 states is that the pair moves together.
- **D-06 / `delegate-agy-d4t`** — `RB01`'s static "every agy invocation is a `run_bounded` argument" scan reads the bridge and the shim but not `tests/contract-check.sh`, which invokes `agy` four times. Widen the loop to three files, and restructure the scanned file so it scans clean.

Purpose: both are coverage holes in checks the project already trusts. `d4t` in particular means an unbounded `agy` call could be added to the test-side script today and nothing in the suite would notice — which is the exact failure mode R11's scan exists to prevent.
Output: one new case, one widened loop, and a mechanical rewrite of seven guard clauses in one file.

This plan uses task-level TDD with an explicit RED gate in each task, for the reason given in plan 06-03: every case in this phase lands in the single file `tests/run-tests.sh`, so one dedicated TDD plan per feature would add serialization waves without adding verification. D-06's RED gate is unusually clean — the widened loop produces a real, measured failure before the fix that makes it pass.
</objective>
