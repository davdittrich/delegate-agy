<objective>
The release gate. Nothing here changes code; everything here decides whether 1.6.2 ships.

- **Success Criterion 3** — prove a fresh `scripts/install.sh` against merged `master` produces launchers that execute, and that both suites pass on that tree. "Against `master`" is pinned to a recorded `GATE_SHA`, resolved from the local repository, because that is the tree carrying this phase's commits and the remote may not have them yet; the gate proves the locally committed state and hands the push-matches-`GATE_SHA` check to ship time.
- **Success Criterion 1 / D-01** — close the five fix tickets whose fixes landed in plans 06-01, 06-03, and 06-04, close the Phase 5 epic, and verify no ticket surfaced by 1.6.2 work is still open. It is a direct application of the project's own recorded rule that follow-ups discovered during work block the release they belong to, not a new policy.
- **Final sign-off** — a human confirms all four criteria against the real install path, which the sandboxed proof deliberately cannot exercise.

Purpose: the roadmap's framing for this phase is that 1.6.2 ships only when nothing it surfaced is still open. This plan is where that becomes a verdict.
Output: a gate record, six closed tickets, and a human sign-off.

The tag itself is not cut here. Criterion 1's wording is "before the tag is cut" — this plan produces the state that makes cutting it legitimate; `/gsd:ship` cuts it.
