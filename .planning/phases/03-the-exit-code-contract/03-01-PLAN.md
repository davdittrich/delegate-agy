## Alternatives Considered

Mechanism choice: how to append `": <stderr>"` only when stderr is non-empty, in a way that one piece of code serves both the plain-text and the JSON form.

- **Bash alternate-value parameter expansion `${var:+word}`** — `bash(1)` §"Shell Parameter Expansion", GNU Bash Reference Manual 5.3 (2025), <https://www.gnu.org/software/bash/manual/bash.html#Shell-Parameter-Expansion>. One expansion produces the whole suffix or the empty string; the same expansion is passed as a `printf` `%s` argument and as a `python3` argv element, so the guard exists in exactly one place. Verified against empty, single-word, multi-word, tab-bearing, and format-specifier-bearing content before this plan was written.
- **Explicit `[[ -n "$x" ]] && _suffix=": $x"` guard building a temporary variable** — `.planning/phases/03-the-exit-code-contract/03-PATTERNS.md` §"D-03's target shape" (2026). Functionally identical; three lines instead of one expansion, and the extra variable is written once and read twice with no other purpose.
- **Conditional inside the `json.dumps` call (Python-side `if`)** — Python `json` module docs, <https://docs.python.org/3/library/json.html> (2025), applied to the shipped shape at `scripts/agy_bridge.sh:724-728` (2026). Rejected outright: it duplicates the emptiness test in a second language, which is the exact structure that let the same bug ship in four places.

**Decided by: LOC.** All three are correct and none has a performance, ecosystem, or maintenance edge over the others; the parameter expansion is one line where the alternatives are three lines and two languages respectively.
