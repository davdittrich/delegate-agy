## Alternatives Considered

### D-03 — mechanism for making the fallback block SIGPIPE-safe

| Rank | Option | Performance | Simplicity / LOC | Ecosystem | Maintenance |
|------|--------|-------------|------------------|-----------|-------------|
| **1 (chosen)** | Producer selects the first match itself; the truncating consumer is never spawned | Best — one fewer process per run | Best — removes a pipeline stage, adds no error handling | bash/POSIX native, no dependency | Best — hazard class eliminated, cannot regress by omission |
| 2 | `\|\| true` on the `RESOLVED=` assignment (the ticket's own suggestion) | Same process count | +1 token, but silently swallows *every* failure in the pipeline, not just 141 | native | Worse — masks a real `claude` failure as an empty `$RESOLVED` |
| 3 | `set +o pipefail` around the pipeline | Same | Needs save/restore to be correct in a copy-pasted block | native | Worst — a copy-pasted fragment that mutates the user's shell options |

Citations: [Pipefail — KodeKloud](https://notes.kodekloud.com/docs/Advanced-Bash-Scripting/Streams/Pipefail/page); [Prevent Exit When Receiving SIGPIPE with Pipefail Set — vandenakker.xyz](https://blog.vandenakker.xyz/posts/prevent-exit-when-sigpipe-received-and-pipefail-set/); [How to Fix 'Broken Pipe' Errors in Bash Pipelines — oneuptime.com, 2026-01-24](https://oneuptime.com/blog/post/2026-01-24-bash-broken-pipe/view) (in-window); [bug-bash mailing list, pipefail with SIGPIPE/EPIPE, 2017-03](https://lists.gnu.org/archive/html/bug-bash/2017-03/msg00179.html).
**Decided by:** user, locked as D-03, explicitly overriding the ticket's own option 2, consistent with this project's Phase 2 D-08 precedent of eliminating a SIGPIPE-hazard class at its source.

### D-04 — mechanism for extracting the doc block into a runnable test

| Rank | Option | Performance | Simplicity / LOC | Ecosystem | Maintenance |
|------|--------|-------------|------------------|-----------|-------------|
