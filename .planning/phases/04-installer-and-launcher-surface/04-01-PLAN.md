## Alternatives Considered

### D-03 — mechanism for making the fallback block survive a truncating consumer

- **Producer-side single-match selection (chosen)** — the python3 expression itself emits at most one line, so the truncating consumer is never spawned and there is nothing left to break the pipe. Removes a process and an entire hazard class rather than suppressing its symptom; cannot regress by omission because there is no longer a pipeline stage to guard. Mechanism grounded in `man 7 pipe`'s capacity semantics (https://man7.org/linux/man-pages/man7/pipe.7.html, 2024) and CPython's SIGPIPE-to-`BrokenPipeError` conversion (`Note on SIGPIPE`, https://docs.python.org/3/library/signal.html#note-on-sigpipe, 2026).
  **Decided by:** maintenance — it is the only option of the three whose failure mode cannot come back.
- **`|| true` on the `RESOLVED=` assignment** — the bead's own suggested minimal fix. Same process count, one extra token. Rejected because it swallows *every* failure in the pipeline, not just the broken-pipe one: a genuinely missing `claude` (rc 127) then silently yields an empty `$RESOLVED` and the user gets the generic "does not match" error instead of "claude is not installed". Cited: GNU Bash manual, `pipefail` / `set -e` interaction (https://www.gnu.org/software/bash/manual/bash.html#index-pipefail, 2025).
  **Decided by:** maintenance — it converts a loud failure into a misleading one.
- **`set +o pipefail` around the pipeline** — same cost, but to be correct in a fragment the user pastes into their own interactive shell it needs a save-and-restore of the caller's shell options. A copy-pasted snippet that mutates the reader's shell state is the worst outcome of the three. Cited: GNU Bash manual, `set` builtin (https://www.gnu.org/software/bash/manual/bash.html#The-Set-Builtin, 2025).
  **Decided by:** simplicity — correct save/restore costs more lines than the chosen fix costs in total.

User locked the chosen option as D-03, explicitly overriding the bead's own option 2, consistent with Phase 2's D-08 precedent of eliminating a broken-pipe hazard class at its source.

### D-03a — which single-match expression (was Claude's Discretion, now locked here)

- **`next((<gen>), "")` (chosen)** — one expression, yields `""` on zero matches. Measured (M5) byte-identical to the pre-fix `head`-truncated output on a single-match reply, and identical again on both zero-match shapes, with rc 0 and no traceback. Cited: `next` with a default, Python library reference (https://docs.python.org/3/library/functions.html#next, 2026); recommended in this exact form by the antigravity reviewer (`04-REVIEWS.md`, Plan 04-01 Suggestions, 2026).
  **Decided by:** simplicity — one expression, one code path, no exception surface.
- **Index `[0]` on the filtered list** — same LOC, but M5 measured rc 1 with an `IndexError` traceback on a zero-match reply, which aborts before the `case` under `-e`. That is the very failure this plan exists to remove, reintroduced through the fix. Cited: list indexing raises `IndexError`, Python tutorial on errors (https://docs.python.org/3/tutorial/errors.html, 2026).
  **Decided by:** simplicity — it needs a `try`/`except` or a length guard to be correct, and then it is no longer one expression.
- **`for` loop with an early `break` in a `-c` program** — behaviorally fine, but it needs a statement separator and a sentinel variable inside a single-quoted shell one-liner embedded in a markdown fence. Cited: in-repo precedent for compact `python3 -c` JSON idioms, `scripts/install.sh:352-356` (confirmed present at these lines, 2026).
  **Decided by:** LOC — strictly more characters in the most character-sensitive place in the file.

CONTEXT.md lists this choice as Claude's Discretion. It is exercised here rather than deferred to the executor because M5 shows one of the three candidate forms is a silent regression.

### D-04 — mechanism for extracting the doc block into a runnable test

- **Content-anchored range extraction (chosen)** — one `sed -n` range print anchored at both ends: start on the line beginning `RESOLVED="$(claude plugin list`, end on a line that is exactly `esac`. Verified this session to select exactly one range per file. Survives doc reordering. Cited: `tests/run-tests.sh:1668-1677` (`_rb_extract`, the in-repo precedent shipped in Phase 1) and `tests/run-tests.sh:1874` (the extract-then-run-under-`bash -c` usage pattern) — confirmed present at these lines, 2026.
  **Decided by:** maintenance — the anchors are the block's own text, so they cannot drift out of sync with it.
- **Nth-fenced-block index via an `awk` counter** — similar LOC and cost, but `agy-setup.md` has 6 fenced bash blocks and `agy-uninstall.md` has 4; any documentation edit silently reindexes and the test then asserts against the wrong block while still reporting green. Cited: `04-RESEARCH.md` "Pattern 4"; `04-PATTERNS.md` "Content-anchored (not line-number-anchored) block extraction for tests" (2026).
  **Decided by:** maintenance — a silently-wrong green test is worse than no test.
- **Keeping a copy of the block in `tests/fixtures/`** — fewest moving parts in the test, but a second copy of a shipped snippet is precisely the drift class `RB02` already exists to catch elsewhere in this suite. Cited: `tests/run-tests.sh:2451-2463` (`RB02`, in-repo, shipped Phase 1, confirmed present 2026).
  **Decided by:** maintenance — it tests the copy, not the thing users paste.

**Decided by (overall):** maintenance. The inline-stub half follows the suite's established convention at `tests/run-tests.sh:3900` (`I9b`).
