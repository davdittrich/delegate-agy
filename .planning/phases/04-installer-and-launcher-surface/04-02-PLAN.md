## Alternatives Considered

### D-01 — where the python3 presence check goes

- **One hoisted check before the `for RC` loop, gated on the consent flag, carrying a flag into the loop (chosen)** — one `command -v` per run instead of one per matched rc file, and the operator sees one warning line instead of up to three. Costs one new variable and about four lines. Directly mirrors the shipped in-repo guards at `scripts/install.sh:279-283` (`_register_tokensave`) and `scripts/install.sh:260-264` (`_agy_detect`), and the hoisted `check_dependencies()` shape in [Bash Scripting Best Practices for Reliable Automation — oneuptime.com, 2026-02-13](https://oneuptime.com/blog/post/2026-02-13-bash-best-practices/view).
  **Decided by:** maintenance — repeating an unchanging fact once per matched file is noise the operator has to filter.
- **Check inside the loop, per matched rc file** — three lines and no new variable, so marginally fewer LOC, but up to three `command -v` calls and up to three duplicate warnings per run. Cited: the same two in-repo analogs, `scripts/install.sh:260-264` and `:279-283` (confirmed present at these lines, 2026), both of which guard once at their own entry rather than per iteration.
  **Decided by:** performance — the check is invariant across loop iterations, so hoisting it is strictly cheaper. Explicitly overridden by the user in D-01.
- **Check inside the existing flag-off arm at `install.sh:234`** — fewest lines of all, but it inverts the logic: that arm is the dry-run path, which never calls python3, so the guard would fire exactly where it is not needed and never where it is. Cited: `scripts/install.sh:234-236` (the dry-run advisory and its `continue`; confirmed present 2026).
  **Decided by:** simplicity — it puts the check on the branch that does not have the dependency.

**Decided by (overall):** maintenance. User locked the chosen option as D-01 ("guard once, before the loop"), with 04-RESEARCH.md's Open Question 1 resolved in favour of its own recommended reading — see Task 2's action for the exact structure and why the dry-run advisory stays untouched.

### D-06 — how the unset-`HOME` precondition is expressed

- **`[[ -n "${HOME:-}" ]] || { echo "ERROR: ..." >&2; exit 1; }` (chosen)** — one line, and the message names the requirement rather than the mechanism that tripped over it. It is already this file's idiom: the refuse-root check directly above it in both files uses the same `echo`-to-stderr-then-`exit` shape. Cited: `scripts/install.sh:37-41` and `scripts/uninstall.sh:15-19` (the in-repo refuse-root analogs); [Check If an Environment Variable is Set in Bash — LinuxSimply, 2023](https://linuxsimply.com/bash-scripting-tutorial/variables/usage/check-if-environment-variable-is-set/).
  **Decided by:** maintenance — it matches the surrounding code exactly, so nothing new has to be learned to read it.
- **`: "${HOME:?ERROR: HOME is not set...}"`** — shortest and POSIX-portable, but bash prefixes its own `script: line N:` framing onto the message, which reintroduces the mechanism-first diagnostic the bead is about; `install.sh`'s own header also commits to `[[ ]]` over `[ ]`. Cited: GNU Bash manual, Shell Parameter Expansion `${parameter:?word}` (https://www.gnu.org/software/bash/manual/bash.html#Shell-Parameter-Expansion, 2025).
  **Decided by:** simplicity — the message is the entire point of the change, and this form does not let us own it.
- **A default-path fallback for an unset `HOME`** — zero extra lines, and the generated wrapper legitimately uses exactly this shape internally. Rejected here for the opposite requirement: the wrapper must degrade to silence on every invocation, whereas these two scripts must not install into a path the user never sees, which on a shared host is also guessable. Cited: `scripts/install.sh:156` (the generated wrapper's own `${HOME:-/nonexistent}`, the shape this option would wrongly copy; confirmed present 2026).
  **Decided by:** maintenance — a silent redirect turns a loud precondition failure into an install the user cannot find. Forbidden by this plan's prohibitions and by the bead's own bead-lock.

**Decided by (overall):** maintenance. This is the bead's own decided fix shape, adopted verbatim by D-06.
