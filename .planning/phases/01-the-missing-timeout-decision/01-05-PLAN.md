**How to scan.** For each of the two scripts:
1. Run `bash -n` on it first, as `I18` does. A file that does not parse cannot be scanned meaningfully.
2. Drop comment-only lines — those whose first non-blank character is a hash — before anything else, so a comment mentioning the variable is neither an occurrence nor a violation.
3. Join backslash-continued lines into single logical lines. This is load-bearing, not tidiness: the bridge's delegation call places `run_bounded` and the agy invocation on different physical lines, so a per-physical-line scan reports a false violation — and the cheapest way to silence a false violation is to invent the allowlist D-13 forbids.
4. For each joined logical line containing the quoted agy-binary expansion, require the same logical line to contain a `run_bounded` invocation followed by the `--` separator ahead of that expansion. Count the ones that do not.
5. Fail if that count is anything other than zero.

**Non-vacuity.** Also fail if the total number of matched occurrences across both scripts is zero. That is a floor, not a count: it holds whether there are five call sites or fifteen, and it exists so that renaming the variable turns the case red instead of green. Do not assert any other number about call sites anywhere in this plan — the count has been stated wrong three times, most recently because this project's own dynamic-model-resolution work added a site, and the roadmap is explicit that a criterion naming a number is correct only until the next commit.

**Zero exceptions.** No allowlist, no skip list, no recognised escape-hatch comment (D-13). `run_bounded` takes its command as arguments and never names the agy binary itself, so no exception is needed; a future site that genuinely cannot be bounded must change the rule in the open. An inline escape hatch is cheaper to add than a decision is to revisit, which is how the unbounded call survived the last release.

## Alternatives Considered

- **A per-physical-line grep for the quoted agy expansion** (https://www.gnu.org/software/grep/manual/grep.html, GNU grep 3.11, 2023): the obvious one-liner, and how a first draft would be written. Rejected because the bridge's delegation call spans backslash continuations with `run_bounded` on one physical line and the invocation on another, so it reports a false violation — and the cheapest way to silence a false violation is the per-line exception D-13 forbids. Joining logical lines first costs one pass and removes the pressure to invent an allowlist. Decided by: simplicity.
- **ShellCheck or another external static analyser** (https://github.com/koalaman/shellcheck, release 0.10.0, 2024): a real parser, immune to the continuation problem and to comment handling. Rejected on two grounds: it does not express this project-specific invariant — no analyser knows that this particular expansion must be an argument to this particular function — and it would add an external tool to a project whose stated tech stack is pure bash with a hand-rolled harness and no package manifest. Decided by: ecosystem.
- **`bash -n` plus a bash-native parse of the scripts' own syntax tree** (https://www.gnu.org/software/bash/manual/bash.html#Shell-Syntax, bash 5.3.15 verified on this host 2026-08-19): would be exact. Rejected because bash exposes no parse tree, so this means writing a shell parser inside the test harness — a large, subtle artefact whose own bugs would be the most likely cause of a false verdict, guarding a file of a few hundred lines. `bash -n` is kept as the precondition the existing `I18` case already establishes; the parse is not. Decided by: LOC.
- **Enforce duplication with a checksum comment inside each block** versus **a direct comparison of the two ranges (chosen)** (https://www.gnu.org/software/diffutils/manual/diffutils.html, GNU diffutils 3.10, 2023): a checksum makes the intent visible in the source. Rejected because it adds a value inside the block that must itself be kept in sync, so a one-sided edit can now fail in two ways instead of one, and a stale checksum is indistinguishable from real drift. Comparing the two ranges needs no bookkeeping. Decided by: maintenance.
