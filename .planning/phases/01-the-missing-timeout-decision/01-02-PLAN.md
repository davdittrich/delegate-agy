## Alternatives Considered

- **Emit the warning from inside `run_bounded`** (`.planning/phases/01-the-missing-timeout-decision/01-CONTEXT.md` D-09, 2026): keeps the announcement next to the code that made the mechanism choice, and needs no probe change. Rejected because the helper is called three times in a single delegating shim run and four when `--version` is involved, so a caller on a coreutils-less host would see the same line repeated per call. The helper stays hermetic; the probe owns the announcement. Decided by: simplicity.
- **Emit nothing at all in the shim, warn only in the bridge** (`.planning/PROJECT.md` § Key Decisions, "Shim degrades silently, bridge fails loud", 2026; superseded by D-01): the shim's historical posture is to never disturb a PATH caller. Rejected because the shim is precisely where the box-wide blast radius lives, so an operator whose `gemini` is now bounded by the weaker mechanism is the one person who most needs to know. stderr does not reach the machine consumers — Octopus and Metaswarm both read stdout and the JSON envelope (https://github.com/nyldn/claude-octopus, 2024). Decided by: maintenance.
- **Give the stdin site a zero kill-after so its `run_bounded` call mirrors today's bare `timeout <secs> cat`** (`timeout --version` → GNU coreutils 9.11, verified 2026-08-19; https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html): would keep the converted line closest to what it replaces. Rejected because coreutils treats a zero duration as *no timeout*, so admitting zero anywhere means `run_bounded` cannot validate its bounds with one rule, and the exact hazard case `SH13` already guards against would reappear at a different site. An escalation that never fires costs nothing. Decided by: simplicity.
