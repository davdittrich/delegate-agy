<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| The test harness → the processes it observes | The outer safety net is itself a process killer; if it signals a group it destroys the evidence the case exists to check. |
| Script → OS signal delivery, with and without a controlling terminal | Job control behaves differently in a terminal-less runner, so the boundary is crossed twice with different guarantees. |
| `run_bounded` → the caller's captured streams and JSON payload | The helper's diagnostics cross here if written to the wrong descriptor. |
| Caller argv → agy argv | Argument boundaries cross the helper; a lost boundary silently changes what agy is asked to do. |

## Alternatives Considered

- **Prove the helper only through the entry points, with no unit-level driver** (`.planning/phases/01-the-missing-timeout-decision/01-CONTEXT.md` D-16, 2026): keeps everything behavioural and needs no extraction machinery. Rejected because the refusal and boundary contracts are unreachable from a call site — every site passes bounds the script has already validated, so the invalid-bound branch would ship untested, and the early-exit-versus-late-exit boundary would need a real agy timed to the second. Extraction is free: the duplication markers already delimit the block.
  Decided by: simplicity.
- **Make the helper sourceable by splitting it into its own file that both scripts source** (https://www.gnu.org/software/bash/manual/bash.html#Bourne-Shell-Builtins, bash 5.3.15 verified on this host 2026-08-19): would make unit testing trivial and drift impossible. Rejected for the same reason plan 01-03 rejects it — the shim must work as a lone drop-in at `~/.local/bin/gemini`, and a sourced file is a runtime path that can go missing on exactly the hosts the fallback exists for.
