<assumption_delta_decision>
**Signal:** pluralization of "fallback" — the scripts previously asked "do we have a `TIMEOUT_BIN`?" at every call site, so the singular noun was the `timeout` binary and each site carried its own mechanism-aware branch.

**Noun now primary:** the *bounded invocation* (`run_bounded`), not the `timeout` binary. Call sites ask nothing about mechanism; mechanism selection is an internal detail of one function.

**Decision: `promote`.** `run_bounded` is promoted to the primary abstraction; coreutils `timeout -k` is demoted to one of its two internal mechanisms (D-04, D-05). This is *not* `add-alongside` — no call site keeps a mechanism-aware branch, and the six `if [[ -n "$TIMEOUT_BIN" ]] … else …` pairs are deleted rather than extended.

**Test encoding the generalized intent:** the D-12/D-13 static scan (plan 01-05, case RB01) *is* that test. It goes red the instant a future call site reintroduces the singular assumption by invoking agy directly. It is an architectural guard, not a lint.
</assumption_delta_decision>

## Alternatives Considered

- **coreutils `timeout -k` as the only mechanism** (`timeout --version` → GNU coreutils 9.11, verified on this host 2026-08-19, recorded in `01-RESEARCH.md` § Sources; https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html): the incumbent, and still the preferred mechanism where the binary exists, because it isolates its child into a new process group and signals the *group*, reaping agy's descendants. Rejected as the *only* mechanism because it is absent on the exact hosts this phase exists for — stock macOS without `brew install coreutils` — where its absence today means either a hard `exit 2` or an unbounded call.
  Decided by: ecosystem.
- **`setsid`-based process-group isolation** (https://man7.org/linux/man-pages/man1/setsid.1.html, man-pages 6.x, 2024): would give the same group isolation without job control. Rejected because `setsid` is itself an optional util-linux/coreutils binary with the same availability gap as `timeout` — it is not present on stock macOS either, so the fallback would need a fallback.
  Decided by: ecosystem.
- **A `python3` subprocess supervisor using `os.setpgrp()`** (https://docs.python.org/3/library/subprocess.html#popen-constructor, Python 3.12 docs, 2024): `python3` is already a declared dependency of this project. Rejected because it adds a hard runtime dependency on the *fallback* path — the one path that exists because a dependency was missing — and contradicts PROJECT.md's "Pure bash by design" constraint.
  Decided by: maintenance.
- **bash `set -m` job control with `kill -- -$pgid` (chosen)** (https://www.gnu.org/software/bash/manual/bash.html#Job-Control; bash 5.3.15 verified on this host 2026-08-19, `01-RESEARCH.md` § Standard Stack): no external binary at all, and empirically confirmed this session to allocate a distinct process group inside command substitution and without a controlling terminal, reaping a SIGTERM-ignoring grandchild within `secs + kill_after`.
  Decided by: ecosystem — it is the only option available on the hosts the fallback is for.
- **PGID lookup via procfs field read, with `ps` as the portable fallback (chosen)** (https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html, man-pages 6.x, 2024) versus **a forked `ps -o pgid=` alone**: the forked form was empirically shown this session to lose a race against a fast-exiting child, and — worse — an unguarded lookup pipeline aborts the whole script under `set -euo pipefail`. The procfs read is a single guarded read; `ps` covers macOS, which has no procfs.
  Decided by: performance.
